`questions.js`에 새 퀴즈 문제를 하나 추가한다. 기존 문제와 같은 형식으로 쓰고, `CLAUDE.md`의 "퀴즈 문제 교차검증 규칙"을 빠짐없이 지킨다.

## 입력

카테고리: $1
난이도: $2

- **카테고리**: 키(`history`, `science`, `geography`, `general`)와 이름(`한국사`, `과학`, `지리`, `일반상식`)을 모두 받는다. 대소문자와 앞뒤 공백은 무시한다.
- **난이도**: `easy` / `medium` / `hard` 가운데 하나다. 대소문자는 무시하고, `쉬움`·`보통`·`어려움`도 차례로 같은 값으로 받는다.
- 둘 중 하나라도 비어 있거나 맞는 값이 없으면 아무것도 고치지 않는다. 쓸 수 있는 값 목록을 보여 준 뒤 멈춘다.

## 0. 시작 전에 문제 수 확인

`app.js`의 `validateQuestions()`는 과목마다 문제가 정확히 `QUESTIONS_PER_CATEGORY`개(지금 10개)인지 검사한다. `PRD.md`에도 "4개 카테고리 × 10문제"라고 정해져 있다. 그래서 그냥 하나를 더하면 검증에 실패한다.

초안을 쓰기 전에 해당 과목의 현재 문제 수를 확인하고, 사용자에게 어느 방식으로 추가할지 묻는다.

1. **기존 문제 교체 (권장)**: 같은 과목의 문제 하나를 새 문제로 바꾼다. 어느 문제를 바꿀지도 사용자에게 묻는다. 새 문제는 바뀌는 문제의 id를 이어받는다.
2. **문제 수 늘리기**: `QUESTIONS_PER_CATEGORY`는 모든 과목에 똑같이 적용된다. 그래서 네 과목에 모두 문제를 더해야 하고, `PRD.md`의 문제 수 표기(F-01, F-10, 데이터 구조 예시, 확인 항목)도 함께 고쳐야 한다. 사용자가 이 방식을 고르면 바꿀 범위를 먼저 보여 주고 다시 확인을 받는다.

사용자가 답하기 전에는 파일을 고치지 않는다.

## 1. 초안 작성

기존 문제를 읽고 다음을 지킨다.

- **형식**: 같은 과목의 기존 문제와 필드 순서, 따옴표, 들여쓰기를 똑같이 맞춘다.

  ```js
  {
    id: "h11",
    difficulty: "medium",
    year: 1443,            // 한국사(history)에만 둔다
    question: "질문?",
    choices: ["보기1", "보기2", "보기3", "보기4"],
    answer: 0,             // 셔플 전 choices의 정답 인덱스(0~3)
    explanation: "해설 1~2문장."
  }
  ```

- **id**: 과목 접두어(`h`, `s`, `g`, `n`)에 두 자리 번호를 붙인다. 교체하면 기존 id를 이어받고, 늘리면 그 과목의 다음 번호를 쓴다.
- **year**: 한국사에만 넣는다. 해설에 나오는 사건 연도와 같아야 한다. 한국사는 `year`로 시대순 정렬되므로 배열 안에서도 연도 순서에 맞는 자리에 넣는다.
- **choices**: 보기는 4개이고 서로 겹치지 않게 쓴다. 오답 3개도 그럴듯해야 하지만 '부분적으로 맞는' 보기가 있으면 안 된다.
- **answer**: 정답 위치가 한쪽에 몰리지 않게 그 과목의 기존 `answer` 분포를 보고 고른다. 게임에서 보기를 섞어 보여 주더라도 데이터는 고르게 둔다.
- **explanation**: 1~2문장으로 쓰고, 정답의 근거가 되는 연도·숫자·인물을 담는다.
- **난이도**: 입력받은 난이도에 맞게 쓴다. 기준은 같은 과목에서 같은 난이도인 기존 문제들이다.
- **주제**: 기존 40문제와 주제나 정답이 겹치지 않게 고른다.
- **피할 문제**:
  - 시점에 따라 바뀌는 사실(인구, 순위, 현직자, 기록 보유자)
  - 정의에 따라 답이 갈리는 문제(가장 긴 강, 가장 큰 사막, 무지개 색 개수 등)
  - 업적을 누구에게 돌릴지 논쟁이 있는 문제

## 2. 스스로 점검

`CLAUDE.md` "문제마다 확인할 것" 체크리스트를 하나씩 확인한다. 최상급·유일성 표현(가장, 최초, 최대, 유일 등)을 썼다면 범위·측정 방법·시점·정의·사건 단계 가운데 빠진 기준이 없는지 본다. 창제/반포, 착공/완공 같은 비슷한 연도도 다시 확인한다.

## 3. 출처 교차검증

- 웹 검색으로 정답과 해설 속 모든 사실(연도·숫자·인물)을 서로 독립적인 출처 2곳 이상에서 확인한다. 실제로 연 페이지의 URL을 남긴다.
- 출처 우선순위는 `CLAUDE.md`를 따른다. 블로그·커뮤니티·AI가 만든 글은 쓰지 않는다.
- 오답 보기 3개가 정답이 될 여지가 없는지도 출처로 확인한다.
- 모델의 기억은 출처가 아니다. 확인이 안 되거나 출처끼리 다르면 추측으로 메우지 않는다. 다툼이 없는 사실만 묻도록 고치거나, 주제를 바꿔 처음부터 다시 쓴다. 두 번 바꿔도 확인되지 않으면 멈추고 사용자에게 묻는다.

## 4. 반영과 기록

1. 검증을 통과한 문제만 `questions.js`에 넣는다.
2. `questions-verification.md`에서 해당 과목 표에 행을 추가한다. 교체했다면 기존 id의 행을 새 내용으로 바꾼다.
   - 형식: `| id | 확인한 주장 | 출처1 | 출처2 | 확인일 | 판정 |`
   - 확인일은 오늘 날짜(YYYY-MM-DD)로 쓴다.
   - 판정은 "추가" 또는 "교체: 원래 문제 요약"으로 쓴다.
   - 직접 열어 읽은 출처에는 **(열람)**을 붙인다.
3. 문제 수를 늘리는 방식을 골랐다면 `app.js`의 `QUESTIONS_PER_CATEGORY`와 `PRD.md`도 함께 고친다.

## 5. validateQuestions() 확인

Node로 `questions.js`와 `app.js`의 `validateQuestions`를 불러와 실행하고 `true`인지 확인한다. 둘 다 브라우저용 파일이므로 DOM에 의존하지 않는 부분만 떼어 실행한다. 실행할 수 없으면 같은 규칙(과목별 문제 수, 보기 4개, answer 0~3, difficulty 값, 한국사 year)을 직접 확인한다. 이 경우 보고에 "validateQuestions 직접 실행 못 함"이라고 밝힌다.
