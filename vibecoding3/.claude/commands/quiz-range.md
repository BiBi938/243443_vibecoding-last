`questions.js`에서 지정한 범위의 문제를 골라 난이도와 정답이 어떻게 분포되어 있는지 확인한다. 파일은 읽기만 하고 고치지 않는다.

## 검토 범위

시작 번호: $1
끝 번호: $2

- 번호는 `questions.js`에 나오는 순서대로 1부터 센다. 과목 순서는 한국사 → 과학 → 지리 → 일반상식이고, 한 과목이 10문제라 1~10은 `h01~h10`, 11~20은 `s01~s10`, 21~30은 `g01~g10`, 31~40은 `n01~n10`이다. 문제 수가 바뀌었을 수 있으니 실제로 파일을 읽어 센다.
- 두 값이 모두 비어 있으면 전체 문제를 검토한다. 시작 번호만 있으면 그 번호부터 마지막 문제까지 검토한다.
- 시작 번호가 끝 번호보다 크면 두 값을 바꿔서 쓰고, 보고에 바꿨다고 적는다.
- 숫자가 아니거나, 1보다 작거나, 문제 수보다 크면 검토하지 말고 쓸 수 있는 범위(예: 1~40)와 번호-id 대응표를 보여 준 뒤 멈춘다.
- 보고 첫 줄에 검토 범위를 적는다. 예: "검토 범위: 5~18번 (h05~s08, 14문제)"

## 확인할 것

### 1. 문제 목록

| 번호 | id | 과목 | 난이도 | 정답 인덱스 | 정답 보기 | 질문 |
|---|---|---|---|---|---|---|

- 정답 인덱스는 `answer` 값(0~3)이고, 정답 보기는 `choices[answer]`의 글자다.

### 2. 난이도 분포

| 난이도 | 배수 | 문제 수 | 비율 | 해당 id |
|---|---|---|---|---|

- 난이도는 `easy`(1배) / `medium`(1.5배) / `hard`(2배) 세 가지다.
- 범위에 두 과목 이상이 걸치면 과목별 난이도 개수도 따로 보여 준다.
- 한 난이도가 범위의 절반을 넘거나 하나도 없으면 치우쳤다고 표시한다.
- 위 세 값이 아닌 `difficulty`가 있으면 오류로 따로 적는다.

### 3. 정답 위치 분포

| 정답 인덱스 | 문제 수 | 비율 | 해당 id |
|---|---|---|---|

- 0~3 네 칸을 모두 보여 준다. 0인 칸도 생략하지 않는다.
- 기대값은 범위 문제 수 ÷ 4이다. 한 인덱스가 기대값의 2배를 넘거나 한 번도 안 나오면 치우쳤다고 표시한다.
- 같은 정답 인덱스가 3문제 이상 연달아 나오면 그 구간을 적는다.
- `app.js`에서 보기를 섞는지 확인하고 결과를 함께 적는다. 게임에서 보기를 섞는다면 파일 안의 정답 위치 치우침은 플레이에 드러나지 않는다. 이 경우 데이터를 정리하는 관점에서만 참고하라고 안내한다.
- `answer`가 0~3 밖이거나 `choices`가 4개가 아니면 오류로 따로 적는다.

## 보고

위 표 세 개를 보여 주고, 표 아래에 다음을 정리한다.

1. 검토한 문제 수와 범위
2. 난이도 치우침 (없으면 "없음")
3. 정답 위치 치우침과 연속 구간 (없으면 "없음")
4. 데이터 오류 (없으면 "없음")

난이도가 적절한지는 모델이 판단한 것이므로 의견으로만 적는다. 고칠지는 사용자에게 맡긴다. 문제 내용이나 정답을 바꾸게 되면 `CLAUDE.md`의 교차검증 규칙(출처 2곳 이상 확인, `questions-verification.md` 기록, `validateQuestions()` 통과)을 따라야 한다고 안내한다.
