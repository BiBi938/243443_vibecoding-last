# 할 일 관리 앱 PRD

작성일: 2026-10-05

## 이 문서를 읽는 방법 (Claude Code용)

이 파일은 구현의 유일한 기준 문서다. 작업을 시작하기 전에 끝까지 읽고, 아래 규칙을 모든 단계에서 지킨다.

- HTML, CSS, 순수 자바스크립트(ES6 이상)만 쓴다. 프레임워크, 라이브러리, npm, 번들러, ES 모듈 `import`를 쓰지 않는다.
- 파일은 `index.html`, `style.css`, `app.js` 세 개다. `index.html`을 더블클릭해 `file://`로 열어도 동작해야 한다. 화면이 번쩍이지 않도록 테마를 먼저 적용하는 짧은 인라인 스크립트는 `index.html`의 `<head>` 안에 두며, 별도 파일로 세지 않는다.
- 앱 상태(할 일, 마지막 카테고리, 테마)는 localStorage의 `todo-app:v1` 키에만 저장한다. 서버와 네트워크 요청이 없다. JSON 내보내기는 사용자가 직접 내려받는 백업 파일이고 가져오기는 사용자가 고른 로컬 파일을 읽는 것이므로, 둘 다 저장 위치를 늘리거나 동기화를 하는 기능이 아니다.
- 상태를 바꾸는 함수(테마 전환과 가져오기 포함)는 상태를 고친 뒤 항상 `save()`와 `render()`를 차례로 부른다.
- 사용자 입력과 가져온 파일의 내용은 `innerHTML`이 아니라 `textContent`로 화면에 넣는다.
- "목표와 비목표"에서 하지 않는다고 적은 기능과 "완료 기준과 범위"의 이후 검토 기능은 만들지 않는다.
- 이 문서에 없는 부분을 결정해야 할 때는 더 단순한 쪽을 고르고, 무엇을 가정했는지 답변에 한 줄로 적는다.
- 작업이 끝나면 "완료 기준과 범위"의 체크리스트로 스스로 점검하고, 통과하지 못한 항목은 숨기지 말고 그대로 보고한다.

## 개요

하루 10~20개의 할 일을 한 화면에서 추가하고, 체크하고, 얼마나 끝냈는지 확인하는 개인용 웹 앱이다. 설치나 로그인 없이 HTML 파일을 브라우저에서 열면 바로 쓸 수 있고, 새로 고침하거나 브라우저를 껐다 켜도 목록이 그대로 남는다.

기존 할 일 앱은 계정, 동기화, 프로젝트, 알림처럼 혼자 쓰기에는 과한 기능이 많다. 이 앱은 반대로 간다. 아침에 오늘 할 일을 적고, 하나씩 지우고, 저녁에 진행률을 한 번 보는 흐름만 빠르게 만든다.

구현은 HTML, CSS, 순수 자바스크립트만 쓴다. 프레임워크, 빌드 도구, 서버가 없다.

## 목표와 비목표

목표는 세 가지다. 첫째, 할 일 하나를 추가하는 데 5초가 넘지 않는다. 입력창에 쓰고 Enter를 누르면 끝이다. 둘째, 20개가 쌓여도 페이지 스크롤 없이 한 화면 안에서 페이지를 넘겨 가며 볼 수 있고, 카테고리별로 걸러 볼 수 있다. 셋째, 어떤 방식으로 창을 닫아도 데이터가 남는다.

하지 않는 것도 분명히 한다. 회원가입과 로그인, 여러 기기 간 동기화, 다른 사람과의 공유, 알림과 반복 일정, 하위 작업은 이번 범위가 아니다. 카테고리도 업무, 개인, 공부 세 개로 고정하고 사용자가 새로 만들 수 없게 한다. 이렇게 잘라내야 순수 자바스크립트 파일 하나로 끝나는 크기가 유지된다.

## 사용 시나리오

사용자는 한 명이고, 매일 같은 브라우저에서 이 앱을 연다. 하루의 흐름은 이렇다.

아침 9시에 앱을 열고 오늘 할 일을 몰아서 적는다. "주간 보고서 초안"을 쓰고 카테고리를 업무로 고른 뒤 Enter, "데이터베이스 과제 3번"은 공부, "세탁소 들르기"는 개인. 이런 식으로 14개를 2분 안에 넣는다. 상단 진행률은 0/14, 0%로 보인다.

낮 동안에는 끝낸 항목의 체크박스를 누른다. 누른 항목은 취소선이 그어지고 흐려지며, 진행률이 5/14, 36%로 바뀐다. 오후에 "주간 보고서 초안"이 "주간 보고서 초안 + 팀장 검토 요청"으로 바뀌면 항목을 더블클릭해 그 자리에서 고친다. 필요 없어진 항목은 삭제 버튼으로 지운다.

공부만 따로 보고 싶을 때는 공부 탭을 누른다. 목록이 공부 항목 4개로 줄고, 공부 진행률 1/4가 함께 보인다. 중간에 실수로 탭을 닫거나 새로 고침해도 다시 열면 모든 상태가 그대로다.

## 기능 요구사항

### 할 일 추가

입력창에 내용을 쓰고 카테고리를 고른 뒤 Enter를 누르거나 추가 버튼을 누르면 목록 맨 아래에 새 항목이 생긴다. 추가 후 입력창은 비워지고 커서가 그대로 남아 연달아 입력할 수 있다. 카테고리 선택은 직전에 고른 값을 유지한다. 업무 항목을 다섯 개 연속으로 넣을 때 매번 다시 고르지 않기 위해서다.

앞뒤 공백을 잘라낸 뒤 내용이 비어 있으면 추가하지 않는다. 길이는 100자로 제한한다. 같은 내용의 중복 항목은 막지 않는다.

### 할 일 수정

항목의 글자를 더블클릭하거나 수정 버튼을 누르면 그 줄이 입력창으로 바뀐다. Enter를 누르거나 다른 곳을 클릭하면 저장되고, Esc를 누르면 고치기 전 내용으로 돌아간다. 수정 중에는 카테고리도 바꿀 수 있다. 내용을 전부 지우고 저장하면 변경을 취소한 것으로 처리하고 원래 내용을 유지한다.

### 할 일 삭제

각 항목 오른쪽의 삭제 버튼을 누르면 확인 창 없이 바로 지워진다. 하루에 스무 번 가까이 쓰는 동작에 매번 확인을 묻는 것은 방해가 된다. 대신 삭제 직후 화면 아래에 "삭제됨 · 되돌리기" 알림이 5초간 떠서 실수를 복구할 수 있게 한다. 되돌리면 항목은 원래 있던 자리로 돌아온다.

완료된 항목을 한꺼번에 지우는 "완료 항목 지우기" 버튼을 목록 아래에 둔다. 이 버튼은 여러 항목을 지우므로 한 번 확인을 받는다.

### 완료 체크

항목 왼쪽의 체크박스를 누르면 완료와 미완료가 번갈아 바뀐다. 완료된 항목은 취소선과 흐린 색으로 표시하고 자리는 옮기지 않는다. 체크하자마자 항목이 아래로 내려가면, 잘못 눌렀을 때 다시 찾기 어렵기 때문이다.

### 카테고리 분류

카테고리는 업무, 개인, 공부 세 가지이며 모든 항목은 정확히 하나에 속한다. 각 항목에는 카테고리 이름이 색이 다른 작은 꼬리표로 붙는다. 색만으로 구분하지 않고 항상 글자를 함께 보여 준다.

목록 위에는 전체, 업무, 개인, 공부 네 개의 탭이 있다. 탭을 누르면 해당 카테고리 항목만 보인다. 각 탭에는 남은 개수를 함께 적는다. 예를 들어 "업무 3"은 업무 중 끝나지 않은 항목이 3개라는 뜻이다. 특정 카테고리 탭을 보고 있을 때 새 항목을 추가하면 입력창의 카테고리가 그 탭의 값으로 맞춰진다.

### 진행률 보기

화면 상단에 진행률 막대와 숫자를 함께 보여 준다. 형식은 "5/14 완료 · 36%"이다. 비율은 완료 개수를 전체 개수로 나눈 뒤 소수점 아래를 반올림한다. 항목이 하나도 없으면 0%가 아니라 "할 일을 추가해 보세요"라는 안내를 보여 준다.

진행률은 현재 선택한 탭을 따른다. 전체 탭에서는 모든 항목 기준, 공부 탭에서는 공부 항목 기준이다. 전체 탭에서는 막대 아래에 카테고리별 수치를 한 줄로 덧붙인다. 예: "업무 2/6 · 개인 2/4 · 공부 1/4". 추가, 삭제, 체크가 일어날 때마다 즉시 다시 계산한다.

### 다크 모드

제목 옆에 테마 전환 버튼을 둔다. 처음 열었을 때는 운영체제의 밝기 설정(prefers-color-scheme)을 따르고, 사용자가 버튼을 누르면 그 선택이 운영체제 설정보다 우선한다. 선택한 값은 저장 객체에 theme 필드("light", "dark", "system")로 함께 저장해서 새로 고침과 브라우저 재시작 후에도 유지한다. 기존에 저장된 데이터에 theme 필드가 없어도 오류 없이 "system"으로 동작해야 한다.

다크 모드에서도 글자와 배경의 대비가 충분해야 하고, 카테고리 꼬리표와 진행률 막대가 각자의 배경 위에서 잘 보여야 한다. 페이지가 열릴 때 밝은 화면이 잠깐 번쩍이고 바로 어두워지는 것은 허용하지 않는다. 테마는 화면을 그리기 전에 가장 먼저 정해져 있어야 한다.

### 순서 바꾸기

할 일 목록의 항목을 위아래로 드래그해서 순서를 바꾼다. 화면에 별도의 이동 버튼은 두지 않는다. 마우스 없이도 순서를 바꿀 수 있도록, 항목 안에 초점이 있을 때 Alt+↑ / Alt+↓로 한 칸씩 옮기는 단축키를 둔다. 순서는 todos 배열 자체의 순서이고, 카테고리 탭에서 걸러 본 상태로 옮겨도 전체 목록에서의 순서가 사용자가 기대한 대로(그 탭 안에서의 앞뒤 관계를 지키며) 유지되어야 한다. 드래그 중 페이지 넘김 화살표 위에 잠깐(0.5초) 머물면 페이지가 넘어가서, 다른 페이지의 자리로도 옮길 수 있다.

### 페이지 넘김

항목이 많아 카드가 화면 높이를 넘게 되면 목록을 페이지로 나눈다. 한 페이지의 항목 수는 고정값이 아니라 지금 화면 높이에 맞춰 계산하고(최소 3개), 창 크기가 바뀌면 다시 계산한다. 목록 아래 가운데에 "‹ 1 / 3 ›" 형태의 페이지 넘김을 두고, 화살표를 누르면 목록이 옆으로 밀려 들어오며 다음/이전 페이지가 보인다. 한 페이지뿐이면 페이지 넘김은 보이지 않는다. 새 항목을 추가하면 마지막 페이지로 이동하고, 탭을 바꾸면 첫 페이지로 돌아간다.

### 화면 배치와 움직임

제목부터 내보내기·가져오기까지 모든 내용은 큰 카드 하나에 담고, 카드 바깥에는 배경 그라데이션이 보인다. 카드는 화면 세로 가운데에 놓이며, 항목 수가 바뀌어 위치가 달라지면 새 위치로 부드럽게 미끄러져 간다. 진행률 막대의 채운 부분은 연한 색에서 진한 색으로 흐르는 그라데이션이고, 채운 부분과 빈 부분의 경계는 연하게 번지듯 이어진다. 운영체제에서 움직임 줄이기를 켠 사용자에게는 이런 움직임을 보여 주지 않는다.

### JSON 내보내기와 가져오기

할 일 목록 아래에 내보내기와 가져오기 버튼을 둔다. 내보내기는 지금 저장된 전체 데이터를 "todo-backup-2026-10-05.json"처럼 날짜가 들어간 이름의 파일로 사용자의 기기에 내려받게 한다. 이건 서버를 거치지 않는, 사용자가 수동으로 하는 백업이며, 여러 기기 간 자동 동기화가 아니다.

가져오기는 사용자가 고른 파일을 읽어서 todos가 배열인지, 그 안의 각 항목에 id, text, category, done이 모두 있는지 검사한다. 형식이 맞으면 지금 목록을 통째로 덮어쓴다는 확인을 받은 뒤 적용하고, 형식이 틀리면 지금 목록은 그대로 두고 "가져올 수 없는 파일이에요"라고 알려준다.

## 화면 구성

화면은 하나뿐이고 다른 화면으로 이동하지 않는다(목록 안의 페이지 넘김만 있다). 폭 600px 안팎의 세로 한 줄 구성이며 위에서 아래로 다음 순서로 놓인다.

1. 가운데 정렬된 제목, 오른쪽 끝의 테마 전환 버튼
2. 진행률 막대와 "5/14 완료 · 36%" 숫자
3. 입력 줄: 내용 입력창, 카테고리 선택, 추가 버튼
4. 탭: 전체 · 업무 · 개인 · 공부 (각각 남은 개수 표시), 같은 줄 오른쪽에 오늘 날짜
5. 할 일 목록: 한 줄에 드래그 손잡이, 체크박스, 내용, 카테고리 꼬리표, 수정 버튼, 삭제 버튼 (항목은 드래그로 순서를 바꾼다)
6. 목록 아래 한 줄: 왼쪽 "완료 항목 지우기" 버튼, 가운데 페이지 넘김(여러 페이지일 때만), 오른쪽 내보내기·가져오기 버튼

입력 줄을 목록 위에 두는 이유는 20개가 쌓여도 스크롤 없이 바로 추가할 수 있어야 하기 때문이다. 목록이 비어 있을 때는 빈 공간 대신 "아직 할 일이 없어요. 위에서 첫 항목을 추가해 보세요."라는 안내를 보여 준다. 휴대폰 폭(360px)에서도 같은 구성이 가로 스크롤 없이 보여야 한다.

## 데이터 모델과 저장

데이터는 브라우저의 localStorage에 저장한다. 서버나 데이터베이스 없이 새로 고침과 브라우저 재시작 후에도 남고, 하루 20개 규모에서는 용량(약 5MB)이 문제가 되지 않는다.

할 일 하나는 다음 필드를 가진 객체다.

| 필드 | 형식 | 설명 | 예시 |
| --- | --- | --- | --- |
| id | 문자열 | 항목을 구분하는 고유값 | "1759633200000-k3f9" |
| text | 문자열 | 할 일 내용, 1~100자 | "데이터베이스 과제 3번" |
| category | 문자열 | work, personal, study 중 하나 | "study" |
| done | 불리언 | 완료 여부 | false |
| createdAt | 숫자 | 만든 시각(밀리초) | 1759633200000 |

화면에 보이는 카테고리 이름은 work는 업무, personal은 개인, study는 공부다.

전체 목록은 배열 하나로 묶어 `todo-app:v1`이라는 키 아래에 JSON 문자열로 저장한다. 키에 버전을 넣어 두면 나중에 필드 구조가 바뀌어도 옛 데이터를 구분해서 옮길 수 있다.

```json
{
  "todos": [
    { "id": "1759633200000-k3f9", "text": "데이터베이스 과제 3번", "category": "study", "done": false, "createdAt": 1759633200000 }
  ],
  "lastCategory": "study",
  "theme": "system"
}
```

저장 규칙은 단순하게 간다. 추가, 수정, 삭제, 체크, 순서 바꾸기, 테마 전환 중 무엇이든 일어나면 배열(또는 해당 필드) 전체를 다시 저장한다. 앱을 열 때는 저장된 값을 읽어 화면을 그린다. 저장된 값이 없거나 JSON이 깨져 있으면 오류를 내지 않고 빈 목록으로 시작한다. theme 필드가 없던 예전 데이터를 열면 "system"으로 취급한다. todos 배열의 순서는 화면에 보이는 순서이자 드래그나 이동 버튼으로 바꾼 순서이기도 하다.

알아 둘 한계가 있다. localStorage는 브라우저별, 기기별로 따로다. 크롬에서 쓴 목록은 엣지에서 보이지 않고, 시크릿 창에서 쓴 내용은 창을 닫으면 사라진다. 브라우저의 사이트 데이터를 지우면 목록도 함께 지워진다.

## 기술 제약과 비기능 요구사항

### 기술 제약

HTML, CSS, 순수 자바스크립트(ES6 이상)만 사용한다. React, Vue 같은 프레임워크와 jQuery 같은 라이브러리, npm과 번들러를 쓰지 않는다. 파일은 `index.html`, `style.css`, `app.js` 세 개로 나누고, `index.html`을 더블클릭해 `file://` 주소로 열어도 동작해야 한다. 이 조건 때문에 ES 모듈 `import`는 쓰지 않는다. 일부 브라우저가 `file://`에서 모듈 로딩을 막기 때문이다.

코드 구조는 한 방향으로 흐르게 한다. 할 일 배열이 유일한 상태이고, 상태를 바꾸는 함수(`addTodo`, `updateTodo`, `deleteTodo`, `toggleTodo`, `moveTodo`)는 배열을 고친 뒤 항상 `save()`와 `render()`를 차례로 부른다. `render()`는 상태(할 일 배열, 현재 탭 `currentFilter`, 테마)만 보고 테마 속성, 목록, 진행률을 통째로 다시 그린다. 20개 규모에서는 전체를 다시 그려도 느려지지 않으므로, 바뀐 부분만 고치는 복잡한 로직은 넣지 않는다.

함수 이름과 역할은 다음으로 고정한다.

| 함수 | 역할 |
| --- | --- |
| `load()` | localStorage에서 읽어 상태를 채운다. 값이 없거나 깨져 있으면 빈 목록 |
| `save()` | 상태 전체를 localStorage에 쓴다 |
| `render()` | 테마를 적용하고, 현재 탭 기준으로 목록, 탭 숫자, 진행률을 다시 그린다 |
| `addTodo(text, category)` | 맨 아래에 새 항목 추가 |
| `updateTodo(id, changes)` | 내용 또는 카테고리 수정 |
| `deleteTodo(id)` | 항목 삭제, 되돌리기용으로 직전 항목과 위치를 기억 |
| `toggleTodo(id)` | 완료와 미완료 전환 |
| `moveTodo(id, toIndex)` | 항목을 todos 배열의 다른 위치로 옮긴다 |

사용자가 입력한 내용은 `innerHTML`이 아니라 `textContent`로 화면에 넣는다. 할 일에 `<b>` 같은 문자가 들어가도 글자 그대로 보이게 하기 위해서다. 가져오기로 불러온 파일의 내용도 같은 방식으로 화면에 넣는다.

순서 바꾸기는 HTML 표준 drag and drop API만 쓰고 별도 라이브러리를 쓰지 않는다. 테마 전환은 `<html>`에 `data-theme` 속성을 붙이고, `style.css`의 색상 CSS 변수(`--bg`, `--surface`, `--text`, `--muted`, `--border`, `--accent`, `--work`, `--personal`, `--study`)만 다크 모드 값으로 다시 정의하는 방식으로 구현하며 새 변수를 추가하지 않는다. 내보내기와 가져오기는 브라우저의 파일 다운로드와 `FileReader`만 쓰고, 서버로 데이터를 보내거나 받지 않는다.

### 비기능 요구사항

지원 브라우저는 최신 버전의 크롬, 엣지, 파이어폭스, 사파리다. 항목 100개 상태에서도 추가, 체크, 탭 전환이 누른 즉시(0.1초 이내) 반영되어야 한다. 처음 열 때는 인터넷 연결 없이도 1초 안에 화면이 뜬다. 외부 글꼴이나 CDN을 쓰지 않으므로 오프라인에서도 똑같이 동작한다.

마우스 없이도 쓸 수 있어야 한다. Tab으로 입력창, 탭, 각 항목의 체크박스와 버튼을 차례로 옮겨 다니고, Space로 체크하고, Enter로 추가와 저장을 한다. 체크박스는 실제 `<input type="checkbox">`를, 버튼은 실제 `<button>`을 써서 화면 낭독기가 읽을 수 있게 한다.

## 완료 기준과 범위

첫 버전은 아래 항목이 모두 통과하면 완성이다.

- [ ] 내용을 쓰고 Enter를 누르면 목록 맨 아래에 항목이 생기고 입력창이 비워진다
- [ ] 공백만 입력하고 Enter를 누르면 아무 일도 일어나지 않는다
- [ ] 항목을 더블클릭해 내용을 고치고 Enter를 누르면 바뀐 내용이 보인다
- [ ] 수정 중 Esc를 누르면 원래 내용으로 돌아간다
- [ ] 삭제 버튼을 누르면 항목이 사라지고, 5초 안에 되돌리기를 누르면 같은 자리에 돌아온다
- [ ] 체크박스를 누르면 취소선이 생기고, 다시 누르면 없어진다
- [ ] 14개 중 5개를 체크하면 "5/14 완료 · 36%"가 보인다
- [ ] 공부 탭을 누르면 공부 항목만 보이고 진행률도 공부 기준으로 바뀐다
- [ ] 항목이 없을 때 진행률 자리에 안내 문구가 보인다
- [ ] 새로 고침(F5) 후에도 항목, 완료 상태, 카테고리가 그대로다
- [ ] 브라우저를 완전히 껐다 켜도 그대로다
- [ ] 할 일에 `<script>alert(1)</script>`를 넣어도 글자 그대로 보이고 실행되지 않는다
- [ ] 마우스 없이 키보드만으로 추가, 체크, 수정, 삭제를 할 수 있다
- [ ] 테마 버튼을 누르면 즉시 어두운/밝은 화면으로 바뀌고, 새로 고침해도 그 선택이 유지된다
- [ ] 운영체제가 다크 모드일 때 처음 열면 버튼을 누르기 전에도 어두운 화면으로 뜬다
- [ ] 항목을 드래그해서 순서를 바꾸면 새로 고침 후에도 그 순서가 유지된다
- [ ] 항목에 초점을 두고 Alt+↑/↓를 누르면 순서가 한 칸씩 바뀐다
- [ ] 항목이 화면을 넘을 만큼 많아지면 페이지가 나뉘고, 화살표로 다음 페이지를 볼 수 있다
- [ ] 내보내기를 누르면 날짜가 포함된 JSON 파일이 내려받아진다
- [ ] 올바른 백업 파일을 가져오면 확인 후 목록이 교체된다
- [ ] 형식이 틀린 파일을 가져오면 기존 목록은 그대로 남고 오류 안내가 보인다

첫 버전에서는 만들지 않고 이후에 검토할 기능은 다음과 같다. 마감일과 오늘 날짜 기준 정렬, 날짜별 완료 기록.

## 이번 버전에서 따르는 결정

구현 중 해석이 갈릴 수 있는 세 가지는 다음과 같이 정해 두고 따른다.

첫째, 목록은 날마다 새로 시작하지 않는다. 하나의 목록이 계속 이어지고, 끝낸 항목은 사용자가 "완료 항목 지우기"로 직접 비운다. 날짜가 바뀔 때 자동으로 정리하는 동작은 넣지 않는다.

둘째, 새 항목은 목록 맨 아래에 붙는다.

셋째, 완료된 항목을 숨기는 "미완료만 보기" 옵션은 만들지 않는다. 완료 항목은 취소선 상태로 목록에 그대로 남는다.
